# VisiScan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expo app that scans visiting cards (front + back), extracts details with Gemini, lets the executive review/edit, saves locally, and shows saved cards in a stack or list view.

**Architecture:** Expo Router app, no backend. Pure logic (Gemini request/parse, search, palette, type scale, row mapping) lives in `src/lib` and is unit-tested with jest-expo. Native concerns (SQLite, SecureStore, scanner, files) are thin wrappers. Screens compose small components; all animation via Reanimated on the UI thread.

**Tech Stack:** Expo SDK 58, TypeScript, pnpm, expo-router, react-native-reanimated, react-native-gesture-handler, expo-sqlite (+ `expo-sqlite/kv-store`), expo-secure-store, expo-file-system, expo-image-manipulator, expo-image-picker (fallback), react-native-document-scanner-plugin 2.x, @shopify/flash-list, expo-haptics, expo-font + @expo-google-fonts (Bricolage Grotesque, Plus Jakarta Sans). Gemini via plain `fetch` to the REST API (no SDK).

**Spec:** `docs/superpowers/specs/2026-10-17-visiscan-design.md`

## Global Constraints

- Package manager pnpm; add packages with `pnpm expo install <pkg>`. `.npmrc`: `node-linker=hoisted`.
- **Do not start the app** (no `expo start`, `run:ios`, `run:android`, `prebuild`). The user does that. Verify with `pnpm test`, `pnpm tsc --noEmit`, `pnpm expo lint`, `pnpm expo export --platform android --platform ios`.
- Read Expo docs pinned to v58 (`https://docs.expo.dev/versions/v58.0.0/...`), not `latest`.
- Gemini key never in the bundle: stored only via `expo-secure-store`, entered in Settings.
- Palette exact: Peach `#FFB59A`, Lilac `#C3B1FF`, Mint `#9EE6C4`, Sky `#A9C8FF`, Butter `#FFE08A`, Rose `#FFB3C7`, Ink `#231C2E`, Paper `#FBF7F2`, Muted `#7D7389`.
- Fonts: Bricolage Grotesque (headings 700/800), Plus Jakarta Sans (body 500/600/700). Never system font for app text.
- No live blur anywhere. Depth = layered shadows, gradients, sheens, inner highlights. Never flat.
- Light theme only. Respect system reduce-motion.
- Text scales with screen size and honours system text size, `maxFontSizeMultiplier` 1.35.
- Layout works on phones + tablets, portrait + landscape.
- Images resized to 1600 px long edge, JPEG quality 0.8 before upload and storage.
- Records: UUID ids, `createdAt`/`updatedAt` ISO strings, schema versioned with migrations.
- Hindi/Indic text: kept exactly as printed. Deviation from spec: iOS and Android already fall back to system glyphs for scripts a custom font lacks, so Noto Devanagari is **not** bundled up front; user checks a Hindi card on device, bundle `@expo-google-fonts/noto-sans-devanagari` only if boxes appear.
- Commits: conventional messages, end with the Claude co-author line (personal repo).

## Review Focus

1. Gemini returns malformed JSON, missing keys, or a "not a card" photo → form still opens with whatever parsed, empty fields blank, no crash. (Task 3 test `parseExtraction tolerates junk`.)
2. Weak network: request hangs → abort at 30 s, show Retry / Fill manually, photos kept. (Task 3 test `extractCard times out`.)
3. Bad/missing key (400/401/403) or quota (429) → distinct messages; key error offers to open Settings. (Task 3 test `extractCard maps http errors`.)
4. Executive searches a number typed without spaces/+91 (`98765`) → matches `+91 98765 43210`. (Task 4 test `digit query ignores formatting`.)
5. Discarding a scan or deleting a contact leaves no orphan photo files. (Task 5 `deletePhotos` + Task 7/8 manual check list.)

### Task 3: Gemini extraction client

**Files:**
- Create: `src/lib/gemini.ts`
- Test: `src/lib/gemini.test.ts`

**Interfaces:**
- Consumes: `CardFields`, `emptyFields`.
- Produces:
```ts
export class ExtractError extends Error { kind: 'key'|'quota'|'network'|'timeout'|'server'|'parse' }
export function buildRequest(images: { base64: string }[]): object; // generateContent body
export function parseExtraction(json: unknown): CardFields;
export function extractCard(images: { base64: string }[], apiKey: string, model: string, timeoutMs = 30000): Promise<CardFields>;
```
- Request: `POST https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent`, header `x-goog-api-key`. Body: one user turn with prompt text + each image as `inline_data` `image/jpeg`; `generationConfig: { temperature: 0, responseMimeType: 'application/json', responseJsonSchema: <schema of CardFields, all required, arrays of strings> }`. Prompt says: images are front and back of one visiting card; copy text exactly as printed (any script); every phone number once, mobiles vs landlines; full multi-line addresses each as one string; anything unplaced goes in `other`; empty string / empty array when absent; never invent.
